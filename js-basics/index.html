JavaScript Fundamentals

바닐라 JS 기초 노트 — 할일 앱으로 익히기

변수, 함수, 배열 메서드, DOM, 이벤트까지 — 실제로 우리가 만든 app.js에 이미 쓰인 코드로 핵심 개념을 정리했습니다. 각 섹션 끝에는 프로젝트에 바로 적용할 수 있는 개선 아이디어를 붙였습니다.

목차 1. 변수 선언 2. 자료형 · 템플릿 리터럴 3. 함수와 화살표 함수 4. 조건문 · 삼항연산자 5. 배열 메서드 6. 객체 · 스프레드 7. 구조분해 할당 8. DOM 조작 9. 이벤트 처리 10. 모듈화 프로젝트 적용표
01

변수 선언 — let · const · var

const는 재할당이 불가능한 값, let은 재할당이 필요한 값에 쓰고, var는 함수 스코프라 블록 스코프를 가진 let/const로 대체하는 것이 요즘 표준입니다.

  • const: DOM 참조, 변경되지 않는 배열/객체의 "바인딩"에 사용
  • let: 값이 바뀌는 카운터, 가변 상태에 사용
  • 객체·배열은 const여도 내부 속성은 바꿀 수 있음 (재할당만 금지)
// app.js 상단
let todos = [];
let nextId = 1;

// DOM 참조는 바뀌지 않으므로 const
const form = document.getElementById("todo-form");
const input = document.getElementById("todo-input");
02

자료형과 템플릿 리터럴

자바스크립트의 기본 타입은 문자열, 숫자, 불리언, undefined/null, 객체(배열 포함)입니다. 문자열 안에 변수를 넣을 때는 + 연결 대신 백틱(`)과 ${}를 쓰는 템플릿 리터럴이 더 읽기 쉽습니다.

  • 문자열: "todo", 숫자: 1, 불리언: true/false
  • 배열과 객체는 참조 타입 — 변수에는 "위치"가 저장됨
  • 템플릿 리터럴은 줄바꿈과 표현식 삽입이 자유로움
// app.js의 render() 함수
const remaining = todos.filter(
  (todo) => !todo.completed
).length;

remainingCount.textContent =
  `남은 할 일: ${remaining}개`;
03

함수 선언식과 화살표 함수

이름이 있고 재사용되는 로직은 함수 선언식(function name() {})으로, 콜백처럼 짧고 한 번 쓰고 버리는 함수는 화살표 함수로 쓰면 코드 성격이 명확해집니다. 화살표 함수는 자신만의 this를 만들지 않는다는 차이도 있습니다.

  • 함수 선언식: 호이스팅되어 파일 어디서든 먼저 호출 가능
  • 화살표 함수: (매개변수) => 표현식 형태로 짧게 작성
  • 콜백(이벤트 핸들러, map/filter 등)에는 화살표 함수가 자연스러움
// 이름이 있는 로직 -> 함수 선언식
function addTodo(text) {
  const trimmed = text.trim();
  if (!trimmed) return;
  todos.push({ id: nextId++, text: trimmed, completed: false });
  render();
}

// 짧은 콜백 -> 화살표 함수
text.addEventListener("click", () => toggleTodo(todo.id));
04

조건문과 삼항 연산자

if는 "실행할지 말지"를 결정하는 문장, 삼항 연산자(조건 ? A : B)는 "어떤 값을 쓸지"를 결정하는 표현식입니다. 값을 바로 할당하거나 문자열에 끼워 넣을 때는 삼항 연산자가 더 간결합니다.

  • early return 패턴: 조건이 안 맞으면 즉시 return
  • 삼항 연산자는 클래스명·텍스트처럼 "값"이 필요할 때 사용
// early return — 빈 문자열이면 추가하지 않음
if (!trimmed) return;

// 삼항 연산자로 클래스명 조합
item.className =
  "todo-item" + (todo.completed ? " completed" : "");
05

배열 메서드 — map · filter · forEach · push

배열을 다룰 때 for문 대신 목적이 드러나는 메서드를 쓰면 코드 의도가 명확해집니다. map은 변환, filter는 선택, forEach는 순회(부수효과), push는 추가입니다.

  • map: 새 배열을 "같은 길이"로 변환해서 반환
  • filter: 조건에 맞는 요소만 남긴 새 배열 반환
  • forEach: 반환값 없이 각 요소마다 작업(화면에 렌더링 등) 수행
// toggleTodo — map으로 완료 상태만 바꾼 새 배열 생성
todos = todos.map((todo) =>
  todo.id === id ? { ...todo, completed: !todo.completed } : todo
);

// deleteTodo — filter로 해당 id만 제외
todos = todos.filter((todo) => todo.id !== id);

// render — forEach로 각 todo를 화면에 그리기
todos.forEach((todo) => { /* li 생성 후 list.appendChild */ });
06

객체와 스프레드 연산자

객체는 { key: value } 형태로 여러 속성을 하나로 묶습니다. 스프레드 연산자(...)는 기존 객체를 복사하면서 일부 속성만 덮어써, 원본을 직접 수정하지 않고 새 객체를 만들 수 있게 해줍니다.

  • 원본을 직접 바꾸지 않는 방식을 "불변성(immutability)" 유지라고 함
  • { ...todo, completed: !todo.completed } = todo를 복사한 뒤 completed만 교체
// 하나의 todo 객체
{ id: 1, text: "장보기", completed: false }

// 스프레드로 복사 + 일부 속성만 변경
{ ...todo, completed: !todo.completed }
// -> { id: 1, text: "장보기", completed: true }
07

구조분해 할당 (Destructuring)

객체나 배열에서 필요한 값만 바로 꺼내 변수로 만드는 문법입니다. 지금 app.js는 todo.text, todo.completed처럼 매번 접근하는데, 구조분해를 쓰면 더 짧고 읽기 좋아집니다.

  • 객체 구조분해: const { text, completed } = todo;
  • 함수 매개변수에서도 바로 구조분해 가능
// 지금 방식
todos.forEach((todo) => {
  item.className = todo.completed ? "completed" : "";
  text.textContent = todo.text;
});

// 구조분해로 개선
todos.forEach(({ id, text: label, completed }) => {
  item.className = completed ? "completed" : "";
  text.textContent = label;
});
08

DOM 조작 — 요소 생성과 변경

DOM(Document Object Model)은 HTML을 자바스크립트 객체로 다룰 수 있게 해주는 구조입니다. createElement로 새 요소를 만들고, textContent로 텍스트를 넣고, appendChild로 화면에 붙입니다.

  • getElementById: 이미 있는 요소 찾기
  • createElement: 새 요소 만들기 (아직 화면에는 없음)
  • appendChild: 실제 화면 트리에 연결
// render() 함수 중 리스트 아이템 생성 부분
const item = document.createElement("li");
item.className = "todo-item";

const text = document.createElement("span");
text.textContent = todo.text;

item.appendChild(text);
list.appendChild(item);
09

이벤트 처리 — addEventListener

사용자의 클릭, 입력, 제출 같은 동작에 반응하려면 addEventListener로 "이 요소에서 이 이벤트가 발생하면 이 함수를 실행하라"고 등록합니다. 폼 제출의 기본 동작(새로고침)을 막으려면 preventDefault()가 필요합니다.

  • submit, click 등 이벤트 타입은 수십 종류
  • 콜백 함수 안에서 event 객체로 상세 정보 접근
// 폼 제출 시 새로고침 막고 addTodo 실행
form.addEventListener("submit", (e) => {
  e.preventDefault();
  addTodo(input.value);
  input.value = "";
});
10

모듈화 — import / export

지금은 app.js 하나에 모든 로직이 있지만, 코드가 커지면 기능별로 파일을 나누고 export/import로 연결할 수 있습니다. HTML에서는 <script type="module">로 불러옵니다.

  • export function: 다른 파일에서 쓸 수 있게 공개
  • import { ... } from "./파일.js": 가져오기
// storage.js
export function saveTodos(todos) {
  localStorage.setItem("todos", JSON.stringify(todos));
}

// app.js
import { saveTodos } from "./storage.js";
⟶

우리 프로젝트에 적용하기

위 개념들은 이미 app.js에 쓰이고 있습니다. 아래는 어디에 쓰였는지와, 더 다듬을 수 있는 지점입니다.

개념 현재 위치 개선 아이디어
let/const todos, nextId 그대로 유지 — 이미 적절히 구분됨
map/filter toggleTodo, deleteTodo 그대로 유지 — 불변성 있게 잘 작성됨
구조분해 미사용 render()의 forEach 콜백에서 { id, text, completed }로 구조분해하면 가독성 향상
클래스 조합 item.className = "..." + (...) item.classList.toggle("completed", todo.completed)로 교체하면 더 명확
이벤트 위임 매 렌더링마다 아이템별 addEventListener list 하나에만 리스너를 달고 e.target으로 분기하면 메모리 낭비 방지
모듈화 app.js 한 파일 localStorage 저장/불러오기를 storage.js로 분리해 새로고침해도 목록 유지
STEP 1 render()의 forEach 콜백을 구조분해 문법으로 바꿔보기
STEP 2 className 문자열 조합을 classList.toggle로 교체
STEP 3 addTodo/toggleTodo/deleteTodo 호출 뒤 localStorage에 저장하고, 시작 시 불러오기
작은 할일 앱 하나에도 변수, 함수, 배열 메서드, DOM, 이벤트 다섯 가지 핵심 개념이 모두 들어 있습니다. 이 개념들이 익숙해지면 더 큰 프로젝트의 코드도 같은 패턴으로 읽힙니다.
